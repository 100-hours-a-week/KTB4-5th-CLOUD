# 2026-10-19 DB 마이그레이션 중 BE 연결 전환 지연으로 인한 쓰기 실패

## 🐞 에러 내용

- 운영 DB를 v1에서 v2로 이전하면서 사용자 요청에서 읽기 전용(read-only) 오류가 약 5분 9초 구간에 걸쳐 관측됐다.
- DB는 약 0.08초 만에 쓰기를 받을 준비가 됐지만, 애플리케이션의 쓰기는 함께 복구되지 않았다. 기존 태스크의 스케줄러에서도 오류가 더 늦게까지 남았다.

## 🔍 원인 분석

- 원본 DB의 쓰기를 차단하고 v2 DB를 승격한 뒤에야 새 BE 배포를 시작했다. 기동·헬스체크·트래픽 전환을 기다리는 동안 기존 v2 BE는 읽기 전용 상태의 v1 DB에 쓰기를 시도했다.
- SSM의 DB 주소를 변경해도 실행 중인 BE의 연결은 바뀌지 않았다. DB 준비 완료와 애플리케이션 연결·트래픽 전환 완료를 별도로 고려하지 못했다.

## ✅ 해결 방법

- **당시 조치:** SSM의 DB 주소를 v2로 변경하고 ECS Blue/Green 재배포를 진행해 새 DB를 사용하는 BE로 트래픽을 전환했다.
- **향후 대비:** 초기 복사·복제 단계에서 새 DB에 연결된 BE를 미리 준비한다. 사전 준비 중에는 운영 트래픽과 쓰기·스케줄러 실행을 차단하고, DB 승격 후 트래픽을 전환한다. 기존 태스크의 잔여 요청과 작업 종료도 확인한다.
- **재검증:** 별도로 발생한 재료 상세 조회 오류로 이전 구간에 k6 수정 요청이 전송되지 않았다. 해당 오류를 먼저 해소하고 실제 API 쓰기를 유지하며 실패·복구 시간과 DB 반영을 확인한다. 사전 준비 방식은 아직 적용·검증하지 않았다.

## 회고

- DB 전환 속도만으로 사용자 중단 시간을 판단할 수 없다. 애플리케이션 연결과 실제 쓰기 성공까지 확인해야 한다.
- 다음 이전에서는 BE 준비 시간을 전환 전에 확보하고, DB 승격·트래픽 전환·기존 작업 종료를 각각 확인한다. 개선 효과는 리허설로 측정한다.
